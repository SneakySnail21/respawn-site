# Respawn: перенос и публикация

Сайт состоит из двух частей: тема `respawn-portal` и плагин `respawn-core`. Живой сайт (регистрация, форум, оценки, закладки, подписки) требует PHP и MySQL. Статичная копия для чтения работает на любом хостинге файлов.

## 1. Хостинг с PHP и MySQL (InfinityFree и аналоги): полный сайт

1. В админке сайта: **Инструменты → Перенос Respawn**. Введите новый адрес (например `https://mysite.infinityfreeapp.com`), нажмите «Скачать архив».
2. В архиве: `database.sql` (адреса уже заменены), `wp-content/` (тема, плагин, картинки) и `INSTALL.txt` с пошаговой инструкцией. Токены, сессии и подключения MCP не попадают в архив.
3. На хостинге: создать сайт и базу MySQL, поставить чистый WordPress, импортировать `database.sql` через phpMyAdmin, залить `wp-content/` по FTP, поставить плагины bbPress, Yoast SEO (по желанию) и Akismet, активировать Respawn Core.
4. Настройки → Постоянные ссылки → «Сохранить».

Что учесть на бесплатных хостингах:
- **Письма.** Отправка почты часто закрыта. Регистрация работает без писем (пароль задаётся на сайте). Для писем-подписок и восстановления пароля добавьте SMTP в `wp-config.php`:
  `define('RSP_SMTP_HOST','smtp.example.com'); define('RSP_SMTP_USER','login'); define('RSP_SMTP_PASS','password'); define('RSP_SMTP_FROM','no-reply@example.com');`
- **Автопубликация Respawn AI** работает с компьютера владельца (`autopost/`) и подключается к новому адресу через Novamira отдельно.
- Нужен PHP 8.0 или новее и расширения `mbstring`, `zip`, `gd` или `imagick`.
- Правила для сжатия и кеширования картинок записываются в `.htaccess` автоматически (блок `Respawn`). Если хостинг не Apache, сайт всё равно работает.

## 2. GitHub Pages (и другой статичный хостинг): копия для чтения

GitHub Pages не выполняет PHP, поэтому там нельзя хранить аккаунты, форум и оценки. Выкладывается снимок: новости, обзоры, карточки игр, форум для чтения.

```
cd tools
node static-export.mjs --public=https://USER.github.io/REPO --main=https://respawn.1c-freelancer.ru --out=dist
node serve.mjs dist 8090        # предпросмотр на http://localhost:8090 (для него --public=http://localhost:8090)
```

Что делает скрипт: обходит живой сайт, сохраняет каждую страницу как `папка/index.html`, скачивает стили, шрифты и картинки, заменяет адреса на `--public`, убирает ссылки на REST API, добавляет страницу `404.html`, `sitemap_index.xml`, `robots.txt` и `.nojekyll`. Формы, которым нужен PHP (вход, лайки, закладки, оценки, комментарии, поиск), скрываются, а сверху показывается плашка со ссылкой на основной сайт (`--main`).

Публикация: содержимое папки `dist` залить в репозиторий (ветка `main`, корень или папка `docs`), затем Settings → Pages → Deploy from a branch. Для своего домена положите рядом файл `CNAME`. Копию нужно пересобирать после новых публикаций (команду можно поставить в Планировщик).

## 3. Что настроено для безопасности и стабильной работы

- Сайт открыт по https; адреса в базе и в содержимом приведены к https.
- Заголовки безопасности (nosniff, X-Frame-Options, Referrer-Policy, Permissions-Policy).
- Закрыты XML-RPC, список пользователей в REST и перебор `?author=N`.
- `robots.txt` не пускает поисковики на личные страницы, поиск и сортировки, а карта сайта (Yoast) указана.
- Страницы входа, регистрации, «Мои материалы», закладок и ленты помечены `noindex`.
- Регистрация: проверочный вопрос, скрытое поле-ловушка, не больше 5 регистраций в час с одного адреса, блокировка входа после 5 неверных паролей на 15 минут.
- Участники не попадают в админку WordPress (кроме настроек профиля), статьи уходят на проверку редакции.
